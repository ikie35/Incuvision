--------------------------------------------------------------------------------
METHODOLOGY OVERVIEW
--------------------------------------------------------------------------------
The artificial intelligence pipeline in IncuVision follows a clean four-stage
lifecycle:
  1. Dataset Collection & Assembly (Multi-Day Candling)
  2. Data Annotation & Cloud Management (Roboflow)
  3. YOLOv8 Model Training (Kaggle GPU)
  4. ONNX Model Optimization, Edge Deployment & Threshold Calibration (Raspberry Pi 5)

================================================================================
STAGE 1: DATASET COLLECTION
================================================================================
- Dataset Composition:
  * The dataset comprised 653 candled egg images captured across critical
    incubation milestones: Day 3, Day 7, Day 10, Day 14, and Day 18.
- Purpose:
  * Expose the neural network to the complete biological progression of embryonic
    development, including early vascular branching (spider veins), embryo eye
    spot formation, fluid opacity expansion, unfertilized clear yolks, and early
    dead-in-shell blood rings.
- Environmental Setup:
  * Images were gathered under high-intensity transillumination (candling) light,
    which illuminates internal egg structures through the translucent shell.

================================================================================
STAGE 2: DATA ANNOTATION & PREPROCESSING (ROBOFLOW)
================================================================================
- Annotation Platform:
  * The dataset was organized and annotated using the Roboflow platform.
- Class Ontology (Binary Classification):
  * Class 0 ('fertile')   : Developed eggs showing active blood vessel networks,
                            embryo movement masses, or advanced dark opacity.
  * Class 1 ('infertile') : Clear eggs showing no vascular development, unfertilized
                            yolks, or non-viable early dead eggs.
- Preprocessing & Sizing:
  * Auto-Orientation: EXIF orientation tags were normalized.
  * Static Resizing: Standardized to 640 x 640 pixels using letterbox padding to
    preserve natural egg proportions without distortion.
- Data Augmentation:
  * Candling-safe augmentations were applied, including horizontal and vertical
    flips, slight tilt rotations (+/- 15 degrees), and brightness adjustments
    (+/- 15%) to account for natural light and placement variations.
  * Hue shifts were strictly avoided to preserve the natural red appearance of
    blood vessels.

================================================================================
STAGE 3: MODEL TRAINING (KAGGLE GPU)
================================================================================
- Architecture:
  * Ultralytics YOLOv8 Nano ('yolov8n-detect', ~3.2 million parameters).
  * Selected for its anchor-free detection head and lightweight computational
    footprint, enabling simultaneous bounding-box localization and classification.
- Training Environment:
  * Executed on a cloud-based GPU instance in Kaggle (NVIDIA Tesla T4).
  * Input Resolution: 640 x 640.
  * Batch Size: 16.
  * Loss Functions: Combined Generalized IoU/CIoU box regression loss and Binary
    Cross-Entropy classification loss.
- Output:
  * The best-performing model checkpoint ('best.pt') was saved based on validation
    mean Average Precision (mAP).

================================================================================
STAGE 4: ONNX OPTIMIZATION, EDGE DEPLOYMENT & CALIBRATION (RASPBERRY PI 5)
================================================================================
A. ONNX Conversion:
   - The trained PyTorch model was exported to Open Neural Network Exchange (ONNX)
     format ('yolov8ncandling.onnx') using standard Opset 12.
   - Fixed static input tensor: 1 x 3 x 640 x 640.
   - Purpose: Eliminates PyTorch runtime dependencies, enabling high-speed,
     standalone CPU execution via ONNX Runtime on the Raspberry Pi 5 (~120 ms latency).

B. Edge System Integration (IncuVision Pipeline):
   - Execution Workflow:
     1. Automatic Candling Audit (Days 7, 10, 18) or on-demand user scan via web app.
     2. Sub-tray candling LED relay is energized.
     3. Raspberry Pi camera captures the full chamber frame.
     4. ONNX Runtime performs full-frame inference.
     5. Detected eggs are sorted top-to-bottom, left-to-right into an 8-Row x 7-Column
        grid (#1 through #56).
     6. Annotated results and fertility percentages are displayed on the dashboard
        and logged to the database.

C. Edge Calibration & Optical Tuning:
   - Non-Maximum Suppression (NMS) Calibration:
     * CONFIDENCE_THRESHOLD was set to 0.15: Accounts for natural camera lens
       vignetting and LED light falloff at tray corners, ensuring dimmer peripheral
       eggs are reliably detected without producing background false positives.
     * IOU_THRESHOLD was set to 0.60: Prevents tightly packed neighboring eggs in
       the 56-cup tray from canceling each other out.
   - Physical Seating:
     * Placing eggs blunt-end (air cell) UP and centered directly over the tray LED
       holes provides maximum transillumination, ensuring high detection accuracy
       across all 56 tray positions.
